**核心洞察：** MapFlow的提出标志着跨模型计算复用在多模型协作中的新可能性。通过将注意力图作为中间状态，MapFlow不仅解决了KV Cache在跨模型场景下的兼容问题，还通过映射、压缩、缓存管理和融合执行，实现了实际的延迟和吞吐收益。这种方法为未来的多模型系统提供了一种高效的计算复用路径，有望在AI Agent应用中得到广泛应用，进一步提升系统的整体效率和响应速度。

## NeurIPS 2026 | 从「先出题」到「先探索」：重新思考Tool-Calling Agent的训练数据合成

> **分类：** 技术前沿解读
> **来源：** [机器之心](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651072774&idx=3&sn=7907f035a6b5b83908acc800cf7b3d96&chksm=85c6d6b18352aac69cfd90d961894766637963a6f3c4e7edc2025fea7f84511689daab664e44&scene=126&sessionid=1794183075#rd)

**核心洞察：** Firefly 提出了一种新的训练数据合成方法，通过反转任务生成的顺序，先在真实环境中探索，再反向出题，从而确保数据的可验证性和环境的可复现性。这一方法不仅解决了现有训练数据的规模化、真实性和可验证性之间的矛盾，还为未来研究提供了一个新的切入点。Firefly 的成功表明，在可验证数据的基础上训练 Agent，可以显著提升其在真实场景中的表现，并具有一定的迁移能力。这项工作为 Tool-Calling Agent 的训练数据研究提供了一个重要的方向，即从「生成更多数据」转向「生成可以被信任的数据」，并为后续研究提供了宝贵的资源和思路。
**内容简介：**

- 现有训练数据的三重困境：现有构造 Tool-Calling 训练数据的方式（人工标注、纯模拟环境下的合成、基于真实工具的前向合成）各有所长，但难以同时做到规模化、真实性和可验证性。
- 反转合成流程：提出 Back-Chaining 方法，先在真实 API 上探索，再根据观察到的结果反向出题，确保 ground truth 的正确性。
- Firefly 框架：包含三个阶段：MCP Server Collection、Task Synthesis 和 Reinforcement Learning，通过构建 Tool Graph 和 DAG Exploration 生成可验证的训练数据。
- Retrieval-Augmented Tool-Call Simulator：解决 Environment Drift 问题，使 RL 训练和评估摆脱对 live API 的依赖，同时保持工具返回的真实性。
- Firefly 数据集：包含 5,144 个可验证任务，覆盖 240 个 server、993 个工具，用于离线 RL 训练和评估。
- 实验结果：Firefly RL 显著提升了 Qwen3-4B 模型在 Firefly 测试集和公开 benchmark 上的性能，表明模型学到了可迁移的 tool-use 行为。
- 未来方向：探索 Back-Chaining 在多轮对话中的应用、更大模型的可验证监督效果，以及 Verified by Construction 的更广泛应用。
